# OAuth Atlas — submission pack


Source: https://github.com/ankushkhakale/OAuth-Atlas

## What it solves

OAuth implementation is often blocked before the token exchange: eligibility, app registration, requested scopes, admin permission and provider review. Atlas makes those gates visible, links the evidence, and separates what an agent can research from what an account owner must do.

## Two-minute walkthrough

1. Browse the app library. Show category/Indian-platform filters and pin a platform. Explain that directory membership is not OAuth verification.
2. Open Gmail. Switch from reading to sending, inspect requirements and the separate effort/wait labels, then tick a step.
3. Compare Slack and GitHub. Point out their different distribution and organization/workspace gates.
4. Research `https://linear.app/developers/oauth-2-0-authentication`. Watch real progress; inspect sources and coverage. Generated plans keep unsupported specifics unconfirmed.
5. Try an unfamiliar app or misspelling. Confirm an identity suggestion where available; otherwise add the provider homepage. Show an incomplete report without claiming OAuth is unsupported.
6. Open My guides, reload a saved report, and use Copy report/Export. Explain that saved reports stay in this browser.
7. Open Evidence & method and the linked Composio managed OAuth directory. Managed application ownership does not remove each user's consent.

## Scope delivered

- App discovery/library and four varied reviewed guides.
- Requirements, blockers, effort/wait separation and agent/human responsibilities.
- Live documentation research with evidence and explicit incomplete outcomes.
- Local saved reports, pins, checklists, comparison and Markdown sharing/export.
- No app login, Firebase, database or paid API dependency.

## Honest limitations

This is a documentation-research tool, not an OAuth execution service. No provider app registration, real token exchange or provider approval is claimed. Public discovery may be unavailable; private/unpublished or unsupported-format docs need a handoff. Exact timelines and eligibility remain unknown unless documented. Live Node retrieval, automated tests and browser/hosted checks are separate evidence; see `VALIDATION.md` for the executed checks.
